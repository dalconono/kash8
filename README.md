# Kash8

[Open the private phone preview](https://kash8-money-coach.filippo-dalconzo06.chatgpt.site)

The browser demo at `dist/index.html` runs with fictional values and requires no dependencies. Open the file locally or use the hosted preview. Choose Payday or Pocket money, pick GBP or EUR and enter a purchase to see the calculation. The one-time approval in Payday is simulated. A terminal demo is also available via `node demo.mjs` on Node.js 24.

## Run the UK bank sandbox

The private Node.js 24 pilot in `banking/pilot.mjs` takes a purchase, upcoming bills and a cash buffer. It sends testers to TrueLayer's hosted consent journey, then calculates the result from one GBP current-account balance. The provider hosts bank sign-in. The app requests one-time data access only and displays the calculation on the web. It uses fictional tester identity information and must be tested with a mock bank.

1. Enable **Data API v3** for a sandbox application in TrueLayer Console. Register the exact HTTPS URL `https://<pilot-host>/bank/return`. Confirm with TrueLayer that hosted data authorisation and one-time connections are enabled for the app.
2. Run `node banking/pilot.mjs` on a private, single-instance Node host with an HTTPS reverse proxy to its loopback port (default `8788`). Route `/bank` and `/bank/return` to the process. Disable request body and callback query logging at the proxy and use host-level rate limits. Restarting the process clears outstanding bank flows.
3. In the host's secret settings set `TRUELAYER_CLIENT_ID`, `TRUELAYER_CLIENT_SECRET`, `KASH8_BANK_ORIGIN` (the exact HTTPS origin, without a trailing slash), and `KASH8_BANK_ACCESS_CODE` (a randomly generated secret of at least 32 characters). Share only the access code with sandbox testers through a private channel.
4. Open `/bank` in a phone browser, provide test figures, select the mock bank and complete the hosted flow. Return in the same browser and select **Read balance and calculate**. Check a refusal, an expired flow, a duplicate submission, missing balance fields and an account outside the supported scope. Run `node --test` for the local suite, which mocks the provider endpoints.
5. Keep the static demo and the current Twilio sample replies separate from the sandbox. The existing Sites preview is a separately published copy.

The pilot fails closed when it cannot identify exactly one GBP current account or establish the cash balance without overdraft. It takes the lower of the booked balance and the available balance less the reported overdraft. The tester supplies bills due before next income and the buffer. The result depends on one account, the returned snapshot and those inputs.

## UK launch requirements

- **Regulatory setup.** Confirm the user-facing account information service, legal entity, complaints responsibilities and regulatory route with a UK payments lawyer and the prospective provider. An API contract alone does not confer permission. Confirm whether a regulated principal will operate the service through Kash8 as its agent or whether Kash8 needs its own FCA registration. Check the exact entity and permissions on the FCA Register. Keep the product to budgeting and cash-flow estimates while investment recommendations, credit broking and debt counselling receive separate perimeter review. [FCA account information service models](https://www.fca.org.uk/firms/agency-models-under-psd2)
- **Bank coverage.** Confirm the contracted Data v3 coverage and the live picker for each bank, account type and requested capability. Test current accounts, available balances, overdraft reporting, transaction history and bank-app returns separately. Publish supported banks once verified. Keep currency support in the calculator distinct from country coverage for connecting accounts. [TrueLayer provider coverage](https://docs.truelayer.com/docs/supported-providers-table)
- **Identity and data protection.** Replace the shared sandbox code with individual user authentication and a server-side owner binding for every connection and query. Complete a DPIA, confirm controller and processor roles, lawful bases, transfers, retention and deletion obligations, and agree how providers handle the data. Build disconnect and deletion, redacted logs, isolated credentials, tenant isolation tests, and procedures to suspend bank access and respond to incidents. Obtain an independent security review before connecting customer accounts. [ICO breach guidance](https://ico.org.uk/for-organisations/report-a-breach/personal-data-breach/personal-data-breaches-a-guide/)
- **Messaging.** Ask Twilio/Meta to confirm the finance and AI use case before committing to WhatsApp. Verify the business sender and approved templates where required, then bind a messaging identity through a signed-in web flow before accepting personal queries. Keep balances, merchant-level data, account identifiers and detailed results inside the signed-in web app for the first release. [Twilio sender registration](https://www.twilio.com/docs/whatsapp/self-sign-up) · [WhatsApp Business Messaging Policy](https://whatsappbusiness.com/policy/)
- **Product expansion.** After balances, integrate transaction requests with separate consent, normalize booking dates, refunds and transfers, and test missing coverage before producing comparisons. Start with one-time consent. Consider recurring consent only after revocation, expiry, reconnection and retention controls work. Request fixed and per-use pricing from the provider and estimate cost per connected active user across bank reads, messages, model use and hosting before setting pilot pricing.

## Conversation and evaluation

Use a general-purpose language model to identify the question, request missing facts and explain calculator results. Give it structured functions to check a purchase, summarise transactions or compare financing scenarios as those features are built. Keep bank credentials and access tokens on the backend. Start with a versioned evaluation set of representative questions, including pending transactions, refunds, internal transfers, missing bills and unclear currency. Use a reviewed UK and EU knowledge base for education. Validate outputs and require the model to ask when an input is unknown.

After the bank flow works on mobile, add SMS entry links. Consider WhatsApp after confirming the business platform eligibility of the specific finance experience. Keep account details inside the signed-in web experience.
